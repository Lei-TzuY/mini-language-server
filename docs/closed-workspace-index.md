# Closed-file workspace indexing

The Nova workspace can index a bounded set of local `*.nova` files that are inside configured workspace folders even when the editor has not opened those files.

## Ownership model

Closed files are never inserted into the live `DocumentStore`. Discovery builds detached immutable syntax/symbol/semantic snapshots and contributes them only to `WorkspaceSymbolIndex`. This preserves the existing open-document ownership chain: document versions, push/pull diagnostics, incremental edits, and live semantic stores continue to describe editor-owned buffers only.

An open document always wins over a disk snapshot with the same RFC-safe URI identity. Opening an equivalent URI removes the detached contribution before the live buffer is indexed. Closing the buffer rereads the current disk file and restores a detached contribution when the file still exists and remains in scope.

Closed snapshots never publish push diagnostics and are not inserted into the live DiagnosticStore. They participate in negotiated `workspace/diagnostic` and single-file `textDocument/diagnostic` pulls through ephemeral immutable diagnostic snapshots: stable duplicate function/parameter/local declaration diagnostics are retained from the detached parse, while function-call errors are recomputed against the exact captured combined workspace for unresolved/ambiguous targets, bounded argument-count mismatches, and bounded argument-type mismatches on uniquely resolved calls using literals plus exact same-snapshot typed parameters, explicit typed locals, literal-initialized locals, local alias chains, direct-call-initialized locals whose unique captured target has an explicit supported result type, and bounded arithmetic/string-concatenation/comparison/logical expression-derived locals. Closed local inference never consults the live workspace index: same-file and cross-file call operands come only from the workspace snapshot set captured for that diagnostic pull, expression leaves reuse exact detached references and explicit captured result annotations, explicit local annotations remain authoritative, and ambiguous, cyclic, mixed, or otherwise unknown evidence remains fail-closed. Closed workspace pulls also validate explicit Int/String/Bool return annotations and explicit Int/String/Bool local annotations against bounded expressions using the same detached literal/reference/local-expression and captured-call evidence; ambiguous or unknown expressions stay conservative. Adapter-level unresolved-name, missing-return, and data-flow diagnostics remain separate until their full policy can be reproduced without closed-only false positives. Closed reports use `version: null` and deterministic `null:<digest>` result IDs, so no detached internal version is presented as a filesystem concurrency claim. Their declarations and parse-tree call sites also participate in existing workspace symbol search, definition/hover/completion, reference scans, call hierarchy, collision checks, and cross-file call resolution for open documents.

## Filesystem boundary

Discovery is deliberately local and bounded:

- only configured local `file:` workspace folders are scanned;
- only files ending in `.nova` are considered;
- symlink roots/files are skipped rather than assigned guessed filesystem identity;
- each file is limited to 2 MiB;
- at most 2048 closed Nova files are indexed per scan;
- source bytes must decode as UTF-8;
- non-local authorities, query/fragment-bearing file URIs, unreadable files, invalid UTF-8, and unsupported shapes fail closed.

URI deduplication reuses the workspace-folder RFC-safe identity rules. Scheme/host case and unreserved percent encoding are normalized, reserved delimiters and path case are not guessed, and the index does not claim realpath, inode, or platform-specific case equivalence.

## Refresh lifecycle

A bounded filesystem scan runs after the LSP `initialized` notification when a workspace folder/root scope exists. The closed index is also reconciled after workspace-folder changes and negotiated `workspace/didCreateFiles`, `workspace/didDeleteFiles`, and `workspace/didRenameFiles`. When the client advertises dynamic `workspace/didChangeWatchedFiles` registration, the server registers one `**/*.nova` watcher for create/change/delete events after a scoped workspace becomes active. Watched-file notifications are accepted only after that tracked registration succeeds, are validated as complete batches, and trigger the same bounded rescan only when at least one in-scope local `.nova` URI can affect the detached index. Create/delete resource notifications use the same relevance boundary. `didClose` restores the single relinquished disk source directly.

The watcher integration is client-mediated LSP state, not an OS-native filesystem service. External edits become visible when the registered client reports them; changes made without a negotiated resource notification or successful watcher event remain outside the server-known workspace snapshot until another documented lifecycle transition refreshes the index. Open buffers continue to override watched disk state. Read-only tooling therefore describes the exact server-known indexed snapshot, not an unobserved later disk state. Workspace diagnostic pulls capture the complete workspace semantic set and reject publication with `Content modified` if folder or workspace identity changes before commit.

Source-mutating tooling is stricter. Before publishing a WorkspaceEdit derived from detached sources, the server rereads the closed inputs whose captured evidence justifies the edit and compares their current UTF-8 text with the captured snapshots. Rename revalidates its detached edit inputs. The closed unresolved-function quick fix revalidates the complete captured closed workspace because the repair depends on the absence of any matching function declaration across that workspace. Drift refreshes the closed index and returns LSP `Content modified` instead of applying stale source ranges.

## WorkspaceEdit versions

When a client negotiates `WorkspaceEdit.documentChanges`, editor-owned files keep their exact captured integer versions. Detached closed files use the LSP `OptionalVersionedTextDocumentIdentifier` form with `version: null`; the server never invents version `0` as a concurrency claim for disk files.

Legacy clients that do not negotiate `documentChanges` continue to receive the existing `changes` representation.

## Deliberate nonclaims

This milestone is not a general filesystem service and does not claim full closed-file diagnostic or repair parity. Closed files still do not receive push diagnostics, remaining advanced data-flow and condition-type diagnostics, or general code-action parity. They do reuse the live exact-snapshot scalar analyzers for `nova.constant-condition`, `nova.division-by-zero`, and `nova.conversion-range`; only `nova.division-by-zero` currently exposes a detached quick fix because its exact diagnosed divisor span is sufficient to justify the shared replacement without additional live state. They expose a bounded detached repair pipeline for diagnostics whose edits can be justified entirely from captured evidence: exact `nova.unresolved-function` produces the shared `Create function` fix; closed `nova.argument-count` reconstructs the exact captured call argument list and adjusts it to the diagnosed arity, closed `nova.argument-type` replaces the diagnosed argument with the deterministic Int/String/Bool literal encoded by the captured diagnostic; closed `nova.return-type` / `nova.local-type` mismatches reuse the same literal-replacement policies as open buffers; closed `nova.missing-return` reuses the same structural return/constant-control-flow proof plus an exact captured-workspace never-call resolver, including transitive inferred never effects and bounded tail-expression arbitration, before offering the shared missing-return insertion repair; closed `nova.unreachable-code` reuses the final nested return/loop-control/constant-dead-branch proof with the same captured never-call resolver, preserves the LSP `Unnecessary` tag, and offers the shared exact-span removal repair; closed typed uninitialized `var` reads reuse exact detached references plus the same nested if/else, return, loop-control, non-fallthrough-loop, and captured never-call definite-initialization proof before offering a conservative declaration initializer repair only when one visible typed declaration can be reconstructed without ambiguity; and closed assignments reuse exact detached reference binding plus the captured expression/local/function-result type lattice to report bounded `nova.assignment-type` and `nova.immutable-assignment`, offering the shared RHS literal repair or a `let`→`var` edit only when the exact captured source uniquely reconstructs the visible declaration. Negotiated document changes use `version: null`, and disk/workspace/folder evidence is revalidated before publication. If the client negotiates `codeAction/resolve` for `edit`, the initial closed action carries an opaque resolve token instead of the edit. The token owns the exact captured workspace snapshot set and folder generation; resolving rereads the captured closed workspace again, rejects disk/workspace/folder drift with `Content modified`, and restores the original `WorkspaceEdit` without regenerating it from newer state. Single-file `textDocument/diagnostic` pulls reuse the exact detached workspace snapshot and return deterministic `null:<digest>` result IDs with unchanged-report support; their direct cross-file diagnostic dependencies are returned through the same `relatedDocuments` contract as open pulls. Closed dependencies keep `null:<digest>` lineage, open dependencies keep their exact integer document-version lineage, and a valid `partialResultToken` streams those direct reports only after the complete mixed dependency set passes the exact commit boundary. Related reports do not recursively nest further `relatedDocuments`. Open buffers retain precedence and take the normal live-document pull path. OS-native watcher ownership, remote workspace providers, symlink identity, module/import path rewriting, and permission-aware filesystem transactions remain separate executable phases.
