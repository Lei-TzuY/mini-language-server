# Nova explicit never-call control-flow effects

Nova already accepts the explicit function result annotation `-> !`. The final product now uses that existing annotation as a bounded semantic control-flow fact for one deliberately narrow call form: a uniquely resolved, top-level standalone call statement.

For a statement such as `halt();`, when the exact current workspace contains exactly one `halt` declaration and its explicit result annotation is `!`, the call closes the current function body's fallthrough path. The existing unreachable-code pipeline can therefore mark the executable suffix after the call as `nova.unreachable-code`, and an explicitly value-returning caller does not receive `nova.missing-return` merely because its only reachable path ends in that never-returning call.

The proof is workspace-semantic rather than name based. Ambiguous function declarations remain unknown, and changing a uniquely resolved target from `-> !` to another result annotation removes the termination fact on the next exact workspace diagnostic publication. Cross-file calls therefore follow the same didChange, close/reopen, same-version replacement, cancellation, and stale-result guarantees as the existing workspace diagnostics pipeline.

The same effect resolver now has a conservative inferred mode for unannotated functions. A uniquely resolved unannotated function is proven never-returning only when its exact current body contains no syntactic `return` anywhere and the existing bounded body proof establishes that every path is closed by proven divergence or another never-returning standalone call. That proof is transitive across uniquely resolved call chains and cycle-safe by exact semantic snapshot + declaration identity. Explicit annotations always win: `-> !` is authoritative, while any other explicit result annotation blocks inferred never even if the implementation body appears divergent. Ambiguous targets, recursive cycles without an independently proven divergence base, and bodies containing any syntactic return remain unknown rather than guessed.

Standalone calls at the top level of any analyzed function or nested brace body participate in the same effect, so a reachable `if` arm can close a value-return obligation, statements after the call can be marked unreachable, and definite-initialization joins can ignore an arm that cannot reach the join. Calls embedded inside another expression, initializer, argument list, condition, or other compound expression are not promoted to termination evidence. Effect inference remains separate from ordinary Int/String/Bool/Unit result typing: proving that a call never returns does not manufacture a value type for that expression. A body containing a syntactic bare `return;` remains conservative for missing-return proof rather than allowing a never call elsewhere in that body to hide a reachable non-value-return path. These restrictions avoid pretending to have a full control-flow/effect system while still allowing exact-workspace never effects to compose transitively.
