# Nova code-action resolve

The final Nova product negotiates `codeAction/resolve` only when the client advertises `textDocument.codeAction.resolveSupport.properties` containing `edit`.

When negotiated, `textDocument/codeAction` still computes and validates the quick fix before deferring its edit. Open-buffer actions retain the exact current diagnostic snapshot plus workspace snapshot set that produced the repair. The bounded closed unresolved-function repair instead retains its exact combined workspace capture and workspace-folder generation at the successful detached action commit boundary; it never creates a synthetic live diagnostic snapshot. The initial action omits `edit` and carries opaque `novaCodeActionResolve` data in both ownership modes.

`codeAction/resolve` restores the captured `WorkspaceEdit`; it never regenerates the edit from a newer document or workspace. Open-buffer resolution succeeds only while the exact diagnostic and workspace identities remain current. Detached resolution requires the exact captured workspace/folder identities and rereads every captured closed workspace input before publication because the unresolved-function repair depends on a workspace-wide absence proof. Same-version diagnostic replacement, document change, close/reopen/open-buffer takeover, workspace or folder replacement, closed disk drift, or another stale lineage returns LSP `Content modified`; detached disk drift also refreshes the closed index. Cancellation is checked again at the final publication boundary.

Clients that do not advertise `edit` resolve support keep the existing eager quick-fix behavior and `codeActionProvider: true`. Nova repair policy remains in the product layer; the generic document, semantic, diagnostic, and workspace stores remain language-independent.
