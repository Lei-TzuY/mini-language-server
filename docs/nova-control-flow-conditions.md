# Bounded Nova control-flow condition semantics

The Nova product recognizes `if (...)` and `while (...)` as control-flow syntax rather than function calls. The generic JSON-RPC, document, syntax, semantic, workspace, and diagnostic stores remain language-independent.

For an exact current semantic/workspace snapshot, each condition expression is evaluated through the existing bounded Nova expression-type pipeline. A known `Bool` condition is accepted. A known non-`Bool` condition produces a deterministic `nova.condition-type` diagnostic over the trimmed condition expression. Unknown, ambiguous, malformed, or unsupported expressions remain conservative and do not produce speculative condition-type diagnostics.

Condition typing composes existing literal, exact semantic reference, uniquely resolved function-result, integer arithmetic, comparison, and logical-expression knowledge. Cross-file function results therefore invalidate and rebind with the same workspace snapshot rules as the existing diagnostics pipeline across document changes and close/reopen transitions. Same-version semantic reanalysis also replaces the derived diagnostic snapshot and binds it to the new exact semantic parent identity rather than relying on the numeric version alone.

When the exact current diagnostic snapshot contains a `nova.condition-type` mismatch, the Nova product exposes focused quick fixes over only the diagnosed trimmed expression. The always-available fallback replaces the expression with the Bool literal `false`. When exact current expression typing identifies an `Int`, an additional repair preserves the expression by rewriting it as `(<expression>) != 0`; a known `String` similarly receives `(<expression>) != ""`. These type-directed actions are recomputed from the current semantic/workspace snapshot and disappear as soon as reanalysis makes the condition Bool or unknown, so stale cross-file type knowledge cannot publish an obsolete repair.

Structural scans run on the Nova trivia-masked code view while diagnostic and quick-fix spans remain anchored to the original source text, so `if (...)` or `while (...)` text inside quoted strings or comments does not create control-flow diagnostics or edits.

The same bounded structural model reports deterministic `nova.unreachable-code` diagnostics for executable suffixes that follow a `return` or a complete `if` / `else if` / `else` chain whose every branch guarantees a return. Analysis now recurses through reachable nested brace bodies, so dead suffixes inside `if`, `else`, and `while` bodies are diagnosed as well as dead suffixes at function-body scope. Once an outer body is known to terminate, its single unreachable suffix owns the remaining span and nested braces inside that already-dead suffix are not diagnosed again. Incomplete branches remain reachable, and comments or quoted strings cannot manufacture terminating statements. Publication continues through the existing exact `SemanticSnapshot` -> `DiagnosticSnapshot` compare-and-commit boundary, so didChange, close/reopen, and same-version semantic replacement cannot retain stale unreachable-code results.

Unreachable-code diagnostics also carry the standard LSP `Unnecessary` diagnostic tag. The language-independent `Diagnostic` value validates the bounded LSP tag vocabulary, while Nova chooses the `Unnecessary` policy for `nova.unreachable-code`; push diagnostics, pull diagnostics, and diagnostic copies embedded in code actions render the tag as LSP `DiagnosticTag.Unnecessary` (`1`). The tag remains part of the exact current `DiagnosticSnapshot`, so an editor cannot receive stale fading metadata after same-version reanalysis, document replacement, or close/reopen.

For an exact current `nova.unreachable-code` diagnostic, the Nova product also exposes `Remove unreachable code`. The quick fix deletes only the diagnosed executable suffix, never the terminating `return` or branch-complete control-flow statement. Action publication additionally checks that the diagnostic still belongs to the current `DiagnosticSnapshot` and that this snapshot is bound to the exact current `SemanticSnapshot`; a superseded same-version diagnostic therefore cannot manufacture an edit after semantic reanalysis. The normal code-action request checkpoints continue to provide cancellation and stale-result suppression around this repair.

Negotiated `textDocument/foldingRange` uses the same exact current semantic/document snapshot and trivia-masked structural view. In addition to complete multiline function bodies, the Nova product publishes deterministic folds for complete multiline `if`, direct `else`, `else if`, and `while` blocks inside those functions. Braces and control-flow-looking text inside comments or quoted strings cannot create folds, single-line blocks are omitted, and stale same-version semantic replacement, cancellation, didChange, and close/reopen continue to use the existing exact-snapshot publication guards.
